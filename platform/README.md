# Native services and Android builds

Cinderbrook Brigade uses Godot 4.5.1 Compatibility. Android package: `com.ethannyakabuski.cinderbrookbrigade`. The development presets use min API 24 / target API 36 with ARM64, x86 and x86_64. `Android` exports a debug AAB; `Android Test APK` exports the installable diagnostic package. These settings and successful exports do not establish Play release eligibility. Production signing and Console publication remain owner work.

## Runtime contract

Register `GodotPlayGameServices` before `Services` in project.godot. Services always processes native callbacks, even when gameplay is paused. The game owns its profile, paused incident and settlement transaction.

- `configure_catalog(catalog)` stores the shared definitions. `unlock(id)` retains a legitimately earned Standard achievement; `submit(id, value)` retains a nonnegative best integer score. `submit_metrics(metrics)` supports catalog entries with optional `metric` and achievement `threshold` fields. Missing metrics do not grant achievements. The application uses Standard achievements; adding Incremental definitions requires corresponding native step submission logic first.
- `set_banner_visible(true)` is for Home/results. Gameplay sets false. Reserve `menu_bottom_reserve(reference)` beneath menu controls and refresh on `menu_bottom_reserve_changed`. Actual banner pixels and Android safe areas are converted once into reference-local units. Android startup can have missing insets; a conservative fallback prevents the entire menu disappearing.
- Call `record_round_completed(stable_round_id)` only after final settlement is durably saved. The service journal durably deduplicates the most recent 256 IDs; the game also guards all earlier paid run IDs. On the Next/Retry transition call `request_interstitial_at_transition()`; every third finalized round creates one opportunity. Results themselves never trigger fullscreen ads. An unavailable opportunity is skipped. Round count and consumed opportunities persist across process death. Consumption is saved before SDK display; an unavailable opportunity stays skipped after restart. If service storage cannot commit, no fullscreen ad is shown. The game's durable settlement prevents a continued incident being paid twice.
- Call `request_rewarded_continue()` only after explicit player opt-in on an eligible failure. `fullscreen_pending(reason)` is synchronous before SDK show. Freeze and checkpoint immediately, clear pointer state, and keep gameplay frozen during `fullscreen_visibility_changed(true)`. Consent/privacy forms use the same lock.
- A real earned callback emits `reward_earned` once so the game can persist a pending earned entitlement tied to the current failed incident. Do not revive or run gameplay at that checkpoint. `reward_finished(true)` is delivered after that request dismisses. Cancelled, missing, failed, duplicate, stale and Web/editor callbacks cannot grant it. The game must bind a continuation to the failed incident, commit it once, refresh the paused world/HUD, and require explicit Resume. No gameplay may run beneath an endcard. If native dismissal never arrives, keep the fullscreen block; restart recovers the saved incident rather than guessing that the ad closed.
- A process termination after a successful earned-checkpoint write can recover that continuation paused on the next cold launch. A termination before the genuine earned callback or before a successful write cannot manufacture a reward. A false completion clears a pending checkpoint if a contradictory display failure is reported. A storage failure must keep the prior durable profile and report the failure honestly.
- `request_sign_in()`, `open_achievements()`, `open_leaderboards(id)`, `request_privacy_options()`, `status()`, `can_reward()` and `services_updated` provide safe UI integration. Offline/Web play and saved progress remain available; neither provides simulated ad rewards.

## Safe initial configuration

`platform/config.json` has Google test mode enabled, blank production unit IDs, disabled Play Games and blank backend mappings. Debug builds force Google sample banner/interstitial/rewarded IDs even if a later release configuration supplies production units. Release test mode also uses samples. The operative AdMob manifest App ID is `[admob] general/android/app_id` in `project.godot`, set to Google's sample `ca-app-pub-3940256099942544~3347511713`; the JSON App ID is reference metadata and does not configure the manifest.

UMP refreshes consent before Mobile Ads initialization and only requests ads for OBTAINED or NOT_REQUIRED. Unknown/failed consent leaves ads off without preventing play. Privacy choices invalidate loaded ads and prior initialization generations. Late callbacks cannot restore an obsolete consent state. The under-age flag defaults false; the owner must configure the actual audience, consent messages, support/privacy information and regional testing before production.

To enable Play Games later, supply the same real numeric game ID in JSON and both presets' `godot_play_game_services/game_id`, plus actual achievement/leaderboard mappings. Configure linked app, OAuth/signing fingerprints and testers in the owner consoles. Blank IDs omit the Android APP_ID metadata resource. Local desired progress persists atomically with backup recovery; acknowledgements are session-only and ambiguous ID-only callbacks cannot acknowledge newer scores. Real authentication/backend delivery is unverified until owner configuration/testing.

## Build and verification

Use the installed matching Godot templates, Java 17 and Android SDK. `platform/prepare_android.py --template <official android_source.zip>` creates ignored Android source only from that template, validates archive paths and retains an existing prepared template. POSIX gradlew mode is repaired to 0755. Never copy another game's generated Android project, credentials or local properties.

`tools/build.ps1` tracks its owned Godot process and serializes each export. Never launch two Android exporters against this project. `platform/tests/validate_platform.py` checks safe configuration/catalog identity and the six vendored libraries; `--artifact <APK-or-AAB>` also checks actual native ELF ABIs and 32/64-bit pairing. `tools/verify_native_alignment.py` checks 64-bit ELF LOAD alignment, without claiming physical 16KB-device execution or Play acceptance.

`platform/tests/run_tests.py --godot <executable>` creates a separate temporary fixture project and isolated APPDATA/LOCALAPPDATA/XDG paths. It uses normal autoload startup, because direct --script can parse third-party classes before their autoload exists. The callback suite covers duplicate/stale/failed rewards, dismissal ordering, cadence, missing insets, stale consent loads, corrupt journals and ambiguous Play Games acknowledgements. These are application-logic fixtures, not native SDK delivery or production-backend evidence. `platform/tests/test_prepare_android.py` tests template preparation independently.

Native acceptance must still exercise a real banner, interstitial, earned and unearned reward dismissal, no background simulation, explicit resume, cold save recovery and touch on the exact final APK. Capture receipts must identify APK hashes and actual logical emulator dimensions. Emulator images are not physical-device evidence.
